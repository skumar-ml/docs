This guide walks through how parents **schedule a free trial class** on the Bergen Debate website using **Acuity Scheduling** (embedded on the public page). For how bookings are saved in the database and processed by the Acuity webhook, see [Technical](/bdc/trial-classes/technical).

Public page: [https://www.bergendebate.com/free-class](https://www.bergendebate.com/free-class)

---

## Select grade, location, and class

On the **Free Class** page, parents choose the **grade range** their student is in and a **location** (Glen Rock, Fort Lee, Livingston, White Plains, or Online). An embedded **Acuity Scheduling** widget lists upcoming trial classes that match those filters.

Each listing shows the **class title**, **date and time**, **duration**, **description** (in-person classes include the address), and how many **spots** remain. The parent clicks **BOOK** for the selected slot.

## Registration form (“Your Information”)

After clicking **BOOK**, the parent sees the **Your Information** step. A summary of the selected class appears at the top (title, duration, date/time, description). The **SELECT CLASS** back link returns to the class list. The **X** on the summary card clears the selected class.

The form collects:

- **First name** and **Last name** (parent)
- **Phone** (with country code)
- **Email** — multiple addresses allowed (comma or enter to add)
- **Student’s Full Name**
- **Student Grade in the Upcoming Semester** (dropdown)
- **Previous experience (PF debate)** — free text per the on-page question
- **Parent’s Primary Email** and **Parent’s Primary Phone Number**
- **Desired Location Offering for Upcoming Semester** — Fort Lee, Glen Rock, Livingston, or Online

All marked fields are required. The parent submits with **BOOK CLASS**.

## After booking

After **BOOK CLASS** succeeds, **Acuity** owns the appointment: confirmation and follow-up emails, calendar links, rescheduling, and cancellation all happen in Acuity’s UI and emails. Trial appointments are **managed in Acuity**; our records stay in sync when Acuity sends webhooks (see [Technical](/bdc/trial-classes/technical)).

## Admin: Retool

### Trial Class Details

The [trial class details](https://bergendebate.retool.com/editor/41fed58a-42df-11f0-bba5-fbecf1466f1d/2025%20Phase%20B/trial_class_details/page1) page lists all **trial class bookings**. **Search** and **filter** apply by parent, date, attendance, and status.

![Image](/images/image-125.png)

For each trial class, the page shows **parent and student details**, **class type**, **scheduled date & time**, and whether emails were sent. **Email logs** are viewable, **notes** are editable, and each trial is **marked purchased or unpurchased** as needed.

### Trial Class Email Automation

[This](https://bergendebate.retool.com/apps/a9f49b14-7e96-11f0-b537-dfd369c571eb/2025%20Phase%20B/Trial%20Class%20Email%20Automation/page1) page is used to manage **Trial Class automation**. Based on the trial class status (Attended or Non-Attended), different **email steps and follow-ups** are configured.

Each step has fields for time delay, email subject, content, and Active/Inactive status so follow-ups align with the trial timeline.

**Attended**

In the **Attended** case, the automation step is currently set to **Inactive**, so the email does not get triggered even after the trial is attended.
