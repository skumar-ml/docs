The [NSD Online Classes Checkout](https://www.nsdebatecamp.com/online-class-checkout) flow lets users enroll in a single online class offering. The checkout page is opened with **URL query parameters** that identify the class and session context; the frontend uses these parameters to call the **get class offerings** API and display available schedules. The user creates or logs into a **Parent Account**, enters **Student Details**, selects one **Class Offering** (schedule) from the offerings returned for that context, chooses a payment method, and is redirected to Stripe. There is one class offering per checkout.

**For more detail,** see the technical docs: [Non-Technical Checkout Flow](/online-class/non-technical/checkout-flow), [Pre-Payment](/online-class/technical/pre-payment), [Payment](/online-class/technical/payment), [Post-Payment](/online-class/technical/post-payment).

**Checkout URL format (with parameters):**

`https://www.nsdebatecamp.com/online-class-checkout?grade_id=...&grade_name=...&session_name=...&session_detail_id=...&class_detail_id=...`

- **grade_id** — MongoDB ObjectId of the grade (e.g. 7th–8th).
- **grade_name** — Display label for the grade (e.g. `7th-8th`).
- **session_name** — Session name (e.g. `Fall`).
- **session_detail_id** — MongoDB ObjectId of the session detail (`class_session_details._id`).
- **class_detail_id** — MongoDB ObjectId of the class (`class_details._id`).

**Missing or invalid parameters:** If required parameters are missing (e.g. `grade_id`, `session_detail_id`, or `class_detail_id`), the checkout page shows an **error state** and does not allow the user to proceed:

- A prominent **error banner** is displayed with the message: **"ERROR! Please go back to the Class Overview page to select a class."**
- A **"Go to Class Overview"** button is shown; clicking it takes the user to the [Class Overview](/online-class/class-overview) page to select a class. Only after selecting a class from the overview (which opens checkout with the correct URL parameters) can the user complete enrollment.
- The **checkout form is disabled** — the user cannot create an account, enter student details, or proceed to payment until they go to Class Overview and select a class.

Based on these parameters, the checkout page fetches **offerings** (schedules with `class_offering_id`) so the user can pick a specific day/time before payment. See **API — get class offerings** below.

**The checkout flow follows a multi-step process:**

Login / Sign-up → Student Details → Class Selection & Payment → Stripe Checkout → Access Content

Each step must be completed before proceeding to the next.

**Step 1: Login / Sign-up**

When a user enters the checkout flow, they must log in or create a **Parent Account** before continuing.

### Step 2: Student Details

Once the parent account is created, the user moves to the **Student Details** tab (second tab).

- **Student Details (required):** First name, last name; optionally student email, grade, gender. These are required for enrollment and stored with the payment record.
- The user completes this step and clicks **Next** to continue. No class selection happens on this tab.

### Step 3: Class Selection and Payment

On the third tab, the user sees **classes** (offerings/schedules) for the context passed in the checkout URL (`grade_id`, `grade_name`, `session_name`, `session_detail_id`, `class_detail_id`). The frontend calls the **get class offerings** API to load the list of schedules; the user selects **one** schedule (which has a `class_offering_id`). Only **one class offering** can be purchased per checkout.

- **After the user selects a class/schedule,** the **payment methods** are shown:
  - **ACH / Bank Transfer**
  - **Credit / Debit Card**
- **When the user selects a payment method,** the **Pay Now** button becomes visible.
- **On click of Pay Now,** the frontend calls **createCheckoutUrlForOnlineClass** and redirects the user to the **Stripe checkout** page for the chosen payment method to complete the purchase.

### Differences from camp checkout and briefs checkout

- **Student Details required** — Online class checkout requires student first name, last name (and optionally email, grade, gender) for enrollment; briefs checkout has no student step.
- **No program id** — Class is identified only by `class_offering_id`; no camp program.
- **Single product per checkout** — One class offering per transaction; backend validates duplicate enrollment and spot availability before creating the Stripe session.
- **Same backend product type** — All online class purchases use `createCheckoutUrlForOnlineClass` and `productType: "online_class"`.

## Technical

The sections below summarize the main APIs and flow. For full implementation detail (auth, redirects, payloads, webhooks, `online_class_payment_details`), see [Pre-Payment](/online-class/technical/pre-payment), [Payment](/online-class/technical/payment), and [Post-Payment](/online-class/technical/post-payment).

**Frontend:** The checkout page reads the URL query parameters (`grade_id`, `grade_name`, `session_name`, `session_detail_id`, `class_detail_id`) and uses them to fetch offerings (see **API — get class offerings**). It then collects email, memberId (from Memberstack/login), student object (first_name, last_name, and optionally email, grade, gender), and the user-selected `class_offering_id`. On **Pay Now** it calls **POST** `createCheckoutUrlForOnlineClass` and redirects to `cardUrl`, `achUrl`, or `payLaterUrl` as appropriate.

### API — get class offerings (used on checkout page)

Offerings are loaded based on the checkout URL parameters. Use one of these endpoints (defined in `serverless.yml`):

- **getClassOfferings** — Best when you have both `class_detail_id` and `session_detail_id` from the URL.
  - **Endpoint:** `GET {apiBaseURL}camp/classes/offerings/list?class_detail_id={class_detail_id}&session_detail_id={session_detail_id}`
  - **Query params:** `class_detail_id` (required), `session_detail_id` (required).
  - **Response:** `success`, `classes` (array with `class_detail_id`, `className`, `description`, `price`, `term_name`, `schedules`). Each schedule has `class_offering_id`, `day`, `start_time`, `end_time`, `total_spots`, `enrolled_count`, `available_spots`. The frontend uses `class_offering_id` when calling `createCheckoutUrlForOnlineClass`.

### API — create checkout URL

- **Endpoint:** `POST {apiBaseURL}camp/createCheckoutUrlForOnlineClass`
- **Body:** `email`, `memberId` (required; user must be logged in); `student` (object with `first_name`, `last_name` required; optional `email`, `grade`, `gender`); `class_offering_id` (required); `successUrl`, `cancelUrl` (required); optional `device`, `deviceUserAgent`.
- **Response:** `cardUrl`, `achUrl`, `payLaterUrl`, `success`. Frontend redirects to the URL for the chosen payment method (card, ACH, or Pay Later).
- **Backend:** `createCheckoutUrlForOnlineClass.py` — validates member, student, class offering; checks duplicate enrollment (same student/email for that class_offering_id) and available spots; gets or creates Stripe customer; creates three Stripe Checkout Sessions (card, us_bank_account, affirm); stores session in `stripe_checkout_customer`; returns the three URLs.

### Flow (online class checkout)

- **Auth:** User must be logged in (Memberstack); frontend sends `email` and `memberId` in the POST body. Backend verifies member exists in `members` collection.
- **Validation:** Backend ensures `student.first_name`, `student.last_name`, `class_offering_id`, `successUrl`, `cancelUrl` are present. It loads `class_offerings` by `class_offering_id`, then `class_session_details` (for price, term_id) and `class_details` (for class name). Price is taken from session detail; card amount includes Stripe fee (2.9% + $0.30).
- **Duplicate / capacity:** Backend checks `online_class_payment_details` for existing enrollment (same classOfferingId and student/parent email) and for spot availability (enrolled count vs total_spots on class_offering). If already enrolled or no spots, returns 400 with an error message.
- **Stripe:** Two sessions are created (card, us_bank_account); each stores a document in `stripe_checkout_customer` with `productType: "online_class"`, `classOfferingId`, `parentEmail`, `studentName`, etc. On successful payment, Stripe webhook and `stripePaymentListener` call `updateOnlineClassPaymentDetails` and insert into `online_class_payment_details`.

### Backend — create checkout URL

- **createCheckoutUrlForOnlineClass (createCheckoutUrlForOnlineClass.py):** Body: `email`, `memberId`, `student` (first_name, last_name required; optional email, grade, gender), `class_offering_id`, `successUrl`, `cancelUrl`, optional `device`, `deviceUserAgent`. Creates Stripe Checkout Sessions for card, ACH, and Pay Later (Affirm). Returns `cardUrl`, `achUrl`, `payLaterUrl`, `success`. Collections used: `members`, `class_offerings`, `class_session_details`, `class_details`, `class_term`, `stripe_customer`, `stripe_checkout_customer`, `online_class_payment_details` (for duplicate and capacity checks). After payment, webhook updates `online_class_payment_details` and sends admin email via `sendOnlineClassSuccessEmailToAdmin`.

### Payment / Stripe

- Payment methods: `card` and `us_bank_account` (ACH). Each has its own Checkout Session and URL.
- After payment, Stripe webhooks and `updateOnlineClassPaymentDetails` record the enrollment in `online_class_payment_details`; user gains access to the class (portal/dashboard). Abandoned carts (no completed payment) can be posted to Slack via `abandonedClassCartSlack`.

### Comparison with other checkouts

- **Camp checkout** uses `createCheckoutUrlsByProgram` / `updateStripeCheckoutDb` with `programId`, Student Details, and optional briefs/supplementary; multi-step camp flow.
- **Briefs checkout** uses `createCheckoutUrlForBrief` or `createCheckoutUrlForBriefEvent` with `briefIds` or `briefEventIds`, no Student Details; standalone briefs-only flow.
- **Online class checkout** uses `createCheckoutUrlForOnlineClass` with one `class_offering_id` and Student Details; standalone online-class enrollment. Checkout URL includes `grade_id`, `grade_name`, `session_name`, `session_detail_id`, `class_detail_id`; offerings are fetched from `camp/classes/offerings/list` or `camp/classes/offerings/{sessionDetailId}`; flow: Login/Sign-up → Student Details (tab 2) → Class Selection & Payment (tab 3: select class → payment methods visible → select method → Pay Now → Stripe) → Access Content.
