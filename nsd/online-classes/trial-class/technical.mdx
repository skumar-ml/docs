This section explains how administrators manage **Trial Classes** using Retool and how users interact with the Trial Class registration page.
Trial classes allow prospective students to attend a session before enrolling. Administrators manage the classes, while users can **view available classes and register for a slot**.

---

# Admin Management (Retool)

Administrators manage trial classes through Retool. This includes creating classes, updating class details, deleting classes, rescheduling classes, and tracking user registrations.

---

## Creating a Trial Class

Admins can create a new trial class by entering the following information.

| Field | Description |
|------|-------------|
| Date | Date the trial class will occur |
| Start Time | Time the class begins |
| End Time | Time the class ends |
| Start Grade | Minimum grade allowed |
| End Grade | Maximum grade allowed |
| Number of Spots | Maximum number of students allowed |

### API Call: Create Trial Class Registration

**API:** `POST /camp/trialClassRegistration`

When the form is submitted:

1. The frontend sends the student and parent information with the selected trial class ID.
2. The backend validates the request fields.
3. The system verifies that the trial class exists.
4. A new registration record is created in the **`trial_class_registrations`** collection.

The `attended` field defaults to **false**.

---

Once created:

- The class is saved in the system.
- If the class date is in the future, it becomes available on the **Trial Class registration page**.

Admins can view all scheduled trial classes in Retool.

Administrators can retrieve registrations using the Trial Class Registration APIs.

**Endpoints**

- `GET /camp/trialClassRegistration`
- `GET /camp/trialClassRegistration/{id}`
- `GET /camp/trialClassRegistration?trial_class_id={id}`

These endpoints allow:

- Viewing all registrations
- Viewing a specific registration
- Viewing registrations for a specific trial class

## Updating or Rescheduling Trial Classes

Admins can update or reschedule existing trial classes when needed.

For example:
- Changing the **date**
- Adjusting the **start or end time**
- Updating the **number of available spots**

Rescheduling allows administrators to move a class to another available **time slot**.

---

## Deleting Trial Classes

Admins can remove a trial class if it should no longer be offered.

Deleting a class:
- Removes it from the system
- Prevents new registrations

## Tracking Attendance


After a trial class occurs, administrators can mark students as attended.

### API Call: Mark Attendance

**API:** `POST /camp/trialClassRegistration/{id}/attend`

When this endpoint is called:

- The system updates the registration record.
- The **`attended`** field is set to `true`.

This action is typically triggered from Retool.

---


## Database Collections

### `trial_class_details`

Stores information about scheduled trial classes.

| Field | Description |
|------|-------------|
| _id | Trial class identifier |
| date | Class date |
| start_time | Start time |
| end_time | End time |
| start_grade | Minimum grade |
| end_grade | Maximum grade |
| number_spots | Maximum students |
| created_on | Creation timestamp |
| updated_on | Last updated timestamp |

---

### `trial_class_registrations`

Stores student registrations.

| Field | Description |
|------|-------------|
| _id | Registration identifier |
| student | Student information |
| parent | Parent contact details |
| trial_class_id | Linked trial class |
| attended | Attendance status |
| created_on | Registration timestamp |

# Frontend Integration

The Trial Class page uses JavaScript to dynamically load available classes, populate form fields, and submit registrations to the backend APIs.

The frontend interacts with the following APIs:

| API | Purpose |
|----|----|
| `/camp/trialClassDetail` | Fetch available trial classes |
| `/camp/paymentGrades` | Fetch available grade options |
| `/camp/trialClassRegistration` | Submit a trial class registration |

---

## Fetching Trial Class Options

When the page loads, the frontend fetches available trial classes and renders them as selectable cards.


### Rendering Logic

Each trial class is rendered dynamically using a template element.

Key display elements:

| CSS Class | Description |
|---|---|
| `.trial-class_option-wapper` | Wrapper for trial class options |
| `.trial-class-grid-container` | Container for all trial class cards |
| `.tc_option-label` | Template used for each trial class option |
| `.trial-class_date` | Displays formatted class date |
| `.trial-class_time-info` | Displays start and end time |
| `.trial-class_grade-info` | Displays grade range |

When a user clicks on a class card, the corresponding radio input is automatically selected.

---

## Grade Dropdown

The grade dropdown is populated dynamically using the grades API.


### Dropdown Element

| CSS Class | Description |
|---|---|
| `.trial-form-select-field` | Grade selection dropdown |

The dropdown is populated with grade values returned from the API.

---

## Trial Class Registration

When the user submits the form, the frontend sends a POST request to the registration API.


### Payload Structure

```json
{
  "student": {
    "first_name": "StudentFirstName",
    "last_name": "StudentLastName",
    "grade": "StudentGrade"
  },
  "parent": {
    "first_name": "ParentFirstName",
    "last_name": "ParentLastName",
    "email": "parent@example.com",
    "phone": "1234567890"
  },
  "trial_class_id": "trial_class_id",
  "previous_experience": "Optional text",
  "landingURL": "Landing page URL"
}
```

# User Registration (Trial Class Page)

Users interact with the **Trial Class page**, where they can view available classes and register for a trial class.
Users **cannot create, edit, delete, or reschedule trial classes**.

---

## Viewing Available Classes

When users visit the Trial Class page, they can see upcoming classes including:

- Date, Time, Grade range, Available spots

Only **future trial classes** are displayed.

---

## Registering for a Trial Class

Parents can register their student by completing a registration form.

### Student Information
- First name, Last name, Grade

### Parent Information
- First name, Last name, Email, Phone number

After submission:
- The student is registered for the selected trial class slot.
- The registration is stored in the system for administrators to review.

---
## Zapier Integration

When a trial class registration is successfully created, the system sends the registration data to a **Zapier webhook**. This enables automated workflows such as:

- Sending confirmation emails to parents
- Adding parents to a CRM or mailing list
- Notifying internal teams (Slack, email, etc.)
- Triggering follow-up automation for enrollment

The webhook is triggered **after the registration is saved in the database**.

If the Zapier webhook fails, the **registration is still created successfully**, and the error is logged in the system.

---

### Zapier Data Payload

The following data is sent to Zapier as a JSON payload.

```json
{
  "id": "registration_id",
  "student": {
    "first_name": "StudentFirstName",
    "last_name": "StudentLastName",
    "grade": "StudentGrade"
  },
  "parent": {
    "first_name": "ParentFirstName",
    "last_name": "ParentLastName",
    "email": "parent@example.com",
    "phone": "1234567890"
  },
  "trial_class": {
    "date": "YYYY-MM-DD",
    "start_time": "HH:MM",
    "end_time": "HH:MM",
    "start_grade": "MinGrade",
    "end_grade": "MaxGrade"
  },
  "previous_experience": "Optional text",
  "landingURL": "Optional URL",
  "attended": false,
  "created_on": "ISO timestamp"
}
```

# Summary
- **Admins (Retool)** can create, update, delete, and reschedule trial classes.
- **Admins** can view registrations and mark attendance.
- **Users** can only view available classes and register for a trial class slot.
- Registration records store complete student and parent details.
