This section explains the technical implementation of the Trial Class system, including database structure, APIs, and the Trial Class page behavior.

The system includes:

- Trial class scheduling
- Student registration
- Attendance tracking
- Admin management through Retool

---

# Core Logic Flow

The Trial Class system operates in three main stages:

1. **Trial Class Creation**
   - Admin creates a trial class through Retool.
   - A record is stored in the `trial_class_details` collection.

2. **Class Retrieval**
   - The Trial Class page fetches available classes using the API.
   - Only classes with `date >= today` are returned.

3. **Student Registration**
   - Parents submit the Trial Class form.
   - A registration record is created in `trial_class_registrations`.

4. **Attendance Tracking**
   - Admin marks attendance through Retool.
   - The `attended` field is updated.

---

# Trial Class Page

## Populating Available Classes

When the Trial Class page loads:

1. The frontend calls the Trial Class Detail API.
2. The API returns all **upcoming trial classes**.
3. Classes are displayed to users.

Displayed information includes:

- Date
- Time
- Grade range

---

## Trial Class Registration

Parents fill out a form containing:

- Student information
- Parent contact details
- Selected trial class

After submission:

1. The frontend sends the data to the Trial Class Registration API.
2. The backend validates the request.
3. A registration record is inserted into the database.

---

# Database Collections

## `trial_class_details`

Stores information about each trial class.

Fields include:

- `date`
- `start_time`
- `end_time`
- `start_grade`
- `end_grade`
- `number_spots`
- `created_on`
- `updated_on`

---

## `trial_class_registrations`

Stores student registrations.

Fields include:

- Student details
- Parent contact details
- Trial class ID
- Attendance status
- Creation timestamp

---

# APIs

The Trial Class system includes APIs for managing classes and registrations.

## Trial Class Detail APIs

Used to manage trial class sessions.

Operations include:

- Create trial class
- Retrieve trial class details
- Update trial class
- Delete trial class

---

## Trial Class Registration APIs

Used to manage student registrations.

Operations include:

- Create registration
- Retrieve registrations
- Filter registrations by trial class
- Mark attendance

---

# System Behavior Notes

- Trial classes in the past are automatically filtered out.
- Registration records default to `attended = false`.
- All registrations reference a specific trial class.
- Admin actions are performed through Retool using the backend APIs.
