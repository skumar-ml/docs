Title: "Trial Class System (Technical)"
---

This section explains how the **Trial Class system** works, including how available classes are displayed on the Trial Class page and how students register for a trial class.

Frontend url:
https://www.nsdebatecamp.com/online-classes/free-trial-class

The system supports:

- Viewing available trial classes
- Student registration
- Attendance status tracking

---

### Overview

The Trial Class system allows prospective students to browse upcoming trial classes and register for them through the Trial Class page.

The process includes three main stages:

1. **Trial Class Retrieval** – The Trial Class page retrieves upcoming classes from the backend.
2. **Trial Class Display** – The frontend renders available trial classes to the user.
3. **Student Registration** – Parents submit a registration form which creates a trial class registration.

Attendance for each registration can later be updated through the system.

---

## Trial Class Page

The Trial Class page allows parents to view available trial classes and register a student.

### Populating Available Classes

When the page loads, the frontend retrieves trial class details from the backend.

**API:** `GET /camp/trialClassDetail`

The system performs the following:

- Retrieves trial classes from the `trial_class_details` collection.
- Filters out past classes (`date < today`).
- Sorts classes by date (earliest first).

The frontend then displays available options showing:
- Date, Time, Grade range

Each trial class option typically includes:

| Field | Description |
|------|-------------|
| start_time | Class start time with date in UTC ISO format |
| end_time | Class end time with date in UTC ISO format |
| start_grade | Minimum grade allowed |
| end_grade | Maximum grade allowed |
| number_spots | Maximum available spots |

## Trial Class Registration

Parents can register their student for a trial class by completing a registration form on the Trial Class page.

### Data Submitted

**Student Details**

| Field | Description |
|------|-------------|
| first_name | Student first name |
| last_name | Student last name |
| grade | Student grade |

**Parent Details**

| Field | Description |
|------|-------------|
| first_name | Parent first name |
| last_name | Parent last name |
| email | Parent email |
| phone | Parent phone number |

**Trial Class Selection**

| Field | Description |
|------|-------------|
| trial_class_id | Selected trial class identifier |

Optional fields may also be submitted:

| Field | Description |
|------|-------------|
| previous_experience | Student's previous experience level |
| landingURL | URL of the page where the registration occurred |

The `landingURL` is typically captured on the frontend using:

This allows tracking which page the user used to register.

---

### API Call: Create Trial Class Registration

**API:** `POST /camp/trialClassRegistration`

When the registration form is submitted:

1. The frontend sends the student and parent information along with the selected trial class ID.
2. The system validates the request fields.
3. The system verifies that the trial class exists.
4. A new registration record is created in the `trial_class_registrations` collection.

The `attended` field defaults to **false**.

## Viewing Trial Class Registrations

Registrations can be retrieved using the Trial Class Registration APIs.

**Endpoints**

- `GET /camp/trialClassRegistration`
- `GET /camp/trialClassRegistration/{id}`
- `GET /camp/trialClassRegistration?trial_class_id={id}`

These endpoints allow:

- Viewing all registrations
- Viewing a specific registration
- Viewing registrations associated with a specific trial class

## Frontend JS Behavior

The Trial Class page uses client-side JavaScript to load available trial classes and handle form submission.

### Page Load

Event: `DOMContentLoaded`

APIs triggered:

| Action | API |
|------|------|
| Load trial classes | `GET /camp/trialClassDetail` |
| Populate grade dropdown | `GET /camp/paymentGrades` |

The returned trial classes are dynamically rendered as selectable options on the page.

---

### Trial Class Selection

Event: `click` on a trial class option.

Behavior:

- The corresponding radio input is selected.
- The selected `trial_class_id` is stored for submission.

---

### Time Display Behavior


The start_time and end_time values for trial classes are stored in the system as UTC ISO datetime strings.

When trial classes are displayed on the frontend, these UTC values are converted to Eastern Time (America/New_York) before being shown to users.

This ensures that all trial class times appear in the correct local timezone for the program, regardless of how the datetime is stored in the backend.

### Form Submission

Event: `submit` on `#trial-class-form`.


## CSS Classes Used for Rendering

The frontend script dynamically renders trial class options using predefined CSS classes.  
These classes are required for the JavaScript rendering logic to function correctly.

| Class | Description |
|------|-------------|
| `.trial-class_option-wapper` | Main wrapper containing the trial class section |
| `.trial-class-grid-container` | Container where trial class options are dynamically inserted |
| `.tc_option-label` | Template element used to clone trial class options |
| `.trial-class_date` | Displays formatted trial class date |
| `.trial-class_time-info` | Displays trial class start and end time |
| `.trial-class_grade-info` | Displays the grade range for the class |
| `.trial-form-select-field` | Grade dropdown field in the registration form |
| `.tc_form-done` | Success message container displayed after successful registration |
| `.tc_form-fail` | Error message container displayed when registration fails |

The JavaScript clones the `.tc_option-label` element and populates it with trial class data returned from the API before appending it to `.trial-class-grid-container`.

## Landing URL Tracking

The system tracks the page where the user started the registration process using a `landingURL` value stored in browser session storage.

This allows the system to record which page the user visited before submitting the trial class form.

### Capturing the Landing URL

The landing URL is typically stored when the user first visits the site.

```javascript
sessionStorage.setItem("landingURL", window.location.href)
```

## Attendance Tracking

After a trial class occurs, the attendance status for a student can be updated.

### API Call: Mark Attendance

**API:** `POST /camp/trialClassRegistration/{id}/attend`

When this endpoint is called:

- The system updates the registration record.
- The **`attended`** field is set to `true`.

## Database Collections

### `trial_class_details`

Stores information about scheduled trial classes.

| Field | Description |
|------|-------------|
| _id | Trial class identifier |
| start_time | Start time |
| end_time | End time |
| start_grade | Minimum grade |
| end_grade | Maximum grade |
| number_spots | Maximum students |
| created_on | Creation timestamp |
| updated_on | Last updated timestamp |

---

### `trial_class_registrations`

Stores student registrations.

| Field | Description |
|------|-------------|
| _id | Registration identifier |
| student | Student information |
| parent | Parent contact details |
| trial_class_id | Linked trial class |
| attended | Attendance status |
| created_on | Registration timestamp |

---

## System Behavior Notes

- Only **future trial classes** are returned by the API.
- Registrations default to **`attended = false`**.
- Each registration references a specific trial class via `trial_class_id`.
- A trial class cannot exceed the configured maximum number of student spots.
